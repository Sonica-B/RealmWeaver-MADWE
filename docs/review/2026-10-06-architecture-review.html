Problem.
Generator.generate(spec) → Asset reads as a one-method interface, but what every caller must know is "Asset.image is uint8 HxWx3 or HxWx4 and Kind is texture or sprite": ten reads of .image across five modules, PNG encoding written twice (bridge and CLI), /generate reporting tileability on a sprite, and nowhere for a mesh, a material set or an animation clip to go without editing all of them.
Solution.
Asset carries a kind-typed payload that encodes itself (bytes plus media type), knows its size, and renders a preview image; the embedder, the seam metrics, the bridge and the CLI ask the payload, never the pixels, and each Generator adapter declares the kinds it makes.

Wins

  • · locality: pixel invariant in one record
  • · leverage: one encode, three callers
  • · interface names kinds; adapters declare theirs
  • · tests: one seam test per payload kind
  • · delete the second PNG encoder
  • · metrics stop assuming pixels
Extends ADR-0003 rather than reopening it: /asset/{id}.png stays the texture route; media-typed assets are additive.

Problem.
A world is one biome: biome, tileset, threshold and region are four attributes of one concept fixed at construction (# ponytail: one region per world), the bridge keeps its own biome, and to learn whether a chunk was created or upgraded the bridge reads world.graph.chunk() before and after the call; the glossary already names the missing module, Region, and an open world is many of them, each with its own layout rules, style vector and, tomorrow, terrain, NPC and quest state.
Solution.
World takes a region map (which region owns which chunk; the single-biome map is the first adapter, a biome-noise map the next), a Region record carries biome, compiled tileset and threshold, the border solve asks the neighbour's region whether it shares a tileset, and request_chunk returns the chunk together with its transition so no caller diffs graph state.

Wins

  • · locality: region facts in one record
  • · leverage: N biomes, zero new call sites
  • · bridge stops reading world.graph
  • · tests: region transitions at the World seam
ADR-0004 kept: Region is already a node kind and the graph stays the source of truth; the ponytail note in world.py names several biomes per world as the upgrade path.

Problem.
ADR-0004 promises that agents write "only validated records", but the graph's interface is five bespoke write methods that spell node attributes by hand, a 60-line validate() that restates the schema (_PARENT_KIND, one INSTANCE_OF per tile, ADJACENT geometry), and a from_json that rebuilds Chunk and TileSet from those attributes a third time; tests reach into graph.g.nodes because the interface has no read for "the records of a kind". An NPC, quest or 3D-region kind touches all three and the tests.
Solution.
Declare each node kind once as a record (kind, parent kind, required fields, edge rules); writes go through one put that validates against the declaration, reads through one records(kind), and validation, JSON and counts derive from the same declarations, so the roadmap's NPC and quest state are new declarations rather than new graph methods.

Wins

  • · locality: the schema in one place
  • · leverage: a new kind is one declaration
  • · validate on write, as ADR-0004 says
  • · tests stop reaching graph.g
ADR-0004 kept (networkx, no database, the same node and edge kinds); this delivers its "validated records" clause rather than contradicting it.

Problem.
Three modules each hold a piece of "what is generating now": the scheduler's cap of two in flight, which World.tick can never reach because it generates inline; the bridge's lock, priority counter and prewarm task, a second scheduler written in asyncio so the player's request beats prewarm; and the bridge's generated and pngs, a second cache beside the world's byte-capped one. Ready events come from the bridge diffing chunk state, not from the module that changed it. Mesh generation at tens of seconds, animation clips and NPC dialogue streams need jobs with progress, cancellation and partial results, which a lock cannot carry.
Solution.
World owns submission, in-flight slots and an event stream; behind it one runner with two adapters, inline (tests, CLI) and a worker per slot (bridge), so the scheduler's cap and priority are real; the bridge keeps routes, one PNG cache fed by the asset payload's encode, and a fan-out of the world's events to WebSocket subscribers.

Wins

  • · locality: in-flight state in one module
  • · leverage: cap, priority, events reach the CLI too
  • · bridge shrinks to routes
  • · tests: "two in flight" reachable through World
  • · delete the lock, the priority counter, the prewarm task
  • · long jobs get progress and cancellation
ADR-0003 kept: the transport (HTTP PNG + chunk JSON, WebSocket events) is unchanged. The ponytail notes in world.py and app.py both already name a worker per slot as the upgrade path.

Solution.
The biome compiles what it loads: a cached tileset, the prompt pair for a spec, the palette for a class, the LoRA path; the YAML gains a schema version and typed blocks validated at load, so callers ask the biome for what they need instead of reading its fields.

  • · leverage: one tileset, three callers
  • · delete prompts.py
  • · tests: the schema tested once, per biome file
ADR-0002 kept: layout rules are still learned from the 12×12 ASCII example map; only who compiles them changes.
Candidate 7 Speculative in-process

Let World hand the Predictor and Scheduler their geometry

Files

  • realmweaver/world/predictor.py — RING · _exit_chunk · rank
  • realmweaver/world/scheduler.py — HORIZON · _distance · cost_s
  • realmweaver/world/world.py — tick · observe_player

Before · geometry baked into both modules

After · a neighbourhood and a cost per kind, supplied by World

Problem.
The predictor ranks the eight-ring of square chunks by casting rays in a plane, and the scheduler prices every job with one world-wide mean cost and prunes by a Chebyshev horizon of two; an open 3D world has regions of unequal size, vertical travel, interiors and portals, and jobs whose cost differs by an order of magnitude (texture, mesh, animation). The measured 2D form works (report: top-3 hit-rate 0.99 against 0.56 for the ring), so the friction is not accuracy; it is geometry baked into two modules rather than supplied by the world.
Solution.
The predictor ranks a candidate set the world supplies (the chunk ring today, region portals tomorrow), and the scheduler prices each job by a measured cost per kind and evicts by a distance the world supplies. Hold until a second geometry exists: one adapter is a hypothetical seam.

Wins

  • · locality: geometry lives in World
  • · leverage: one predictor for 3D regions
  • · cost per kind, not a world mean
  • · speculative: wait for the second adapter
No ADR affected. Depends on Candidate 3 for the region map that would supply the neighbourhood.

Problem.

Solution.
